# 程序升级

从 1.3 开始，「偏好设置 → 程序升级」用于升级 CopyCopy 本身。追更订阅里的「检查更新」仍用于漫画章节。

## 使用

- 默认启动后检查正式版本，发现新版时显示顶部提示；可以在升级偏好中关闭并保存。
- Windows 安装版：检查程序更新 → 查看更新说明 → 下载升级包 → 重启并安装。下载显示大小、速度和进度，SHA512 校验成功后才允许安装。退出程序不会自动安装。
- 下载、AI 整理或 PDF 导出仍在进行时，安装会提示等待；任务完成后可以再次点击安装。
- Windows 便携版：检查版本后，打开对应的官方发布页下载新版。退出旧程序，替换 exe，保留同级的 `config`、`out`、`logs` 和 `cache`。
- 更新使用应用当前的代理设置。网络失败可重试，也可直接从官方发布页下载。

1.2 及之前的版本没有程序升级入口，需要手动安装一次 1.3。此后安装版可以从应用内升级到未来正式版本。
只有已经发布到 GitHub Releases、并附带更新元数据的正式版本，才能成为升级来源；PR 的构建产物不会自动成为正式更新。

## 数据保存

安装版从 1.3 开始将漫画、设置及队列保存在 `%APPDATA%\CopyCopy\data`，与被安装程序替换的文件分开。
便携版和开发环境保持原有数据位置。Chromium 的阅读进度、外观等用户偏好仍使用原来的用户配置目录。

新安装程序在运行旧版卸载器之前，先将注册的旧安装目录中的 `config`、`out`、`logs`、`cache` 复制到上述用户目录。
复制失败或发现两处均已有数据时会停止安装，保留旧安装；需先退出旧程序再迁移。不会合并或覆盖两套已有漫画库。
早期因安装目录不可写而已保存在 `%APPDATA%\CopyCopy` 根目录的数据，会继续使用原来的位置，避免隐藏已有漫画库。
可以在「网络与数据」中查看实际使用的数据目录。

## 发布正式版本

1. 修改 `package.json` 和锁文件中的版本号，提交到 `master`。
2. 在该提交上创建并推送匹配的稳定版本标签，例如 `v1.3.0`。
3. `Publish Windows release` 工作流先验证标签匹配版本、提交属于 `master`，再运行 Linux / Windows 检查、真实 Electron UI 测试和 Windows 打包。
4. 检查通过后，一次发布安装包、便携版、安装包的 `.blockmap` 和 `latest.yml` 到 GitHub Releases。

更新源固定为公开仓库 `mkktop/copycopy`。应用无需 GitHub Token；发布使用 GitHub Actions 内置令牌，仅发布步骤有写入权限。
普通 PR、`master` 提交和手动构建都使用 `--publish never`，只生成可审查的构建产物。

## 验证

- `npm run typecheck`、`npm run format:check`、`npm test`。
- `npm run test:ui` 验证原有漫画下载、阅读和设置流程。
- `npm run test:update-ui` 在真实 Electron 中使用标准 `NsisUpdater` 和本地服务器，验证检查失败重试、下载进度、SHA512 拒绝损坏包、重新下载、安装前活动检查、偏好持久化和便携版入口。
- 测试替代工厂仅由测试脚本通过 esbuild 注入，未引入生产代码或生产 IPC；测试不会执行下载的安装程序。
- Windows CI 对打包后的 `latest.yml`、安装包 SHA512、更新源和 blockmap 进行检查；还会实际安装、模拟旧目录、再次升级，并逐文件校验漫画及配置保持不变。
